# Component rules (Atomic Design + shadcn)

## Three layers

1. **`src/components/ui/` — shadcn primitives.**
   - Generated by the shadcn CLI (`npx shadcn@latest add <name>`).
   - **Never hand-edit** these files. If a primitive needs a tweak that the CLI doesn't support, wrap it instead.
2. **`src/components/customized/` — project-wide composed components.**
   - Wrappers around shadcn primitives that bake in project conventions (label + error states for `Input`, masked variants, `DataTable`, `StandardForm`, `ConfirmationModal`, `DatePicker`, etc.).
   - Use these in feature code instead of raw primitives whenever a customized version exists.
3. **Route-private `_components/` — feature-specific atoms/molecules/organisms.**
   - Live next to the page they serve.

## Atomic split (apply within `_components/` and `customized/`)

| Layer | Purpose | Examples |
| --- | --- | --- |
| `atoms/` | Smallest reusable bits, no domain logic | Button wrappers, badges, single cards |
| `molecules/` | Composition of atoms, light state | Search field, info card with actions |
| `organisms/` | Stateful sections: modals, steps, lists | `EditUserDataModal`, `InscriptionPaymentStep` |
| `pages/` (optional) | View-level composition, called by `page.tsx` | `InscriptionListPage` |

## Authoring rules

- Use **`forwardRef`** for low-level controls that may need refs (Input, Select, etc.).
- Customized components must accept and merge `className` via `cn()` so callers can extend styles.
- Customized form controls must accept `error: boolean` and `errorMessage?: string` for compatibility with react-hook-form `formState.errors`.
- Prefer **composition over props explosion**. If you find yourself adding a 6th boolean prop, split into smaller components.
- A component file exports its component as default (or named) — keep one component per file unless they are tightly coupled atoms.
- Naming: `PascalCase` for components and files (`EditUserDataModal.tsx`). Hooks: `useXxx`.

## When to promote a component

- Local in `_components/` → used by **a single route**.
- Promote to `app/(<group>)/_components/` → used by **multiple routes inside the same group**.
- Promote to `src/components/customized/` → used by **multiple groups / the entire app** OR encodes a project-wide UX pattern.

## Don't

- ❌ Don't reach into `src/components/ui/` to override styles inline; wrap the primitive in `customized/` instead.
- ❌ Don't bypass atomic structure for "simplicity" — the folders are the documentation.
- ❌ Don't put domain logic (API calls, business rules) inside atoms or molecules.
